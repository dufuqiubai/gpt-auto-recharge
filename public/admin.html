Settings

                
Self-service activation concurrency and maintenance mode take effect as soon as you save, with no service restart. Telegram and hCaptcha each have their own Save button. Settings are stored in MySQL and survive a container restart (do not use docker compose down -v).

            


            
            

                
Third-party top-up API (protocol)

                

                    When this is on, site redemption submits the order to a third-party GPT top-up platform and polls its status. The local activation flow is not used.
                    Cards and proxies are taken from the Card pool and Proxy pool and sent with the order.
                

                

                    
Enable third-party top-up API (local activation is not used while this is on)

                    If Stripe shows a One more step challenge during checkout, a captcha platform (createTask/getTaskResult) is tried first for the passive checkbox.

Browser pool

                
A resident Chromium process with a local profile cache. Tasks attach over CDP, each with its own context. This page refreshes every 2 seconds.

            


            

                

                    
Slot sizing notes

                

                

                    
The browser pool is a resident Chromium plus a local profile cache. Tasks attach over CDP, and each order still gets its own context (sessions are not shared). Each slot uses about 400–550 MB of memory.

                    

                        Proxies: slots are not pinned to a proxy. When a task starts, an enabled proxy is chosen at random from the Proxy pool and applied to that task Context (see proxy=yes in Runtime logs).
                        Different tasks can use different IPs, so accounts do not share one residential IP. Proxies are managed on the Proxy pool page, separate from the browser pool.
                    

                    

                        
                            

                                Scenario
                                Suggested slots
                                Notes
                            

                        
                        
                            

                                Everyday volume
                                4–8
                                A safe default. Match it to site concurrency in Settings.
                            

                            

                                Peak / 128 GB dedicated
                                8–16
                                Add slots when memory allows. Watch CPU and the ~28 GB used by other projects.
                            

                            

                                Ceiling
                                ≤24
                                Capped by BROWSER_POOL_MAX_SIZE. Filling every slot is not recommended.
                            

                        
                    

                    

                        Persistence: set BROWSER_POOL_SIZE=8 and MAX_CONCURRENT_ACTIVATIONS=8 in the server .env, then run docker compose up -d --force-recreate app.
                        Apply and reload on this page changes the running process only. After a container restart, .env wins.

Run mode

                

                

                    
                    
                

                

                    Off: each task cold-starts its own Chromium (separate from the session login path, which is steadier to debug).

                    On: reuse a warm slot and skip about 5–10s of startup. The switch takes effect immediately and is stored in MySQL.
                

            


            

                

                    
Pool settings

                

                

                    
                    
                    
                

                

                    Reload closes idle slots and warms them again. Slots in use finish their task first. The change is stored for the running process (a container restart still follows the BROWSER_POOL_SIZE environment variable, which you can set in .env).
